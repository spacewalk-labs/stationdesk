# 문서 공유 (share-docs)

문서 내용을 정리하고 하나의 링크로 전달할 때 씁니다. 단순한 글은 Markdown으로 작성하고, 그림·표·입력 폼·탐색 기능이 도움이 될 때 HTML을 만듭니다.

## 박스 정보 읽기

작업 전에 `/opt/stationdesk/state/box-facts.md`를 읽습니다. 이 파일에서 공유 폴더 위치, 이 박스의 주소, 앱 주소와 링크 규칙을 확인합니다. 경로나 도메인을 추측하거나 이 문서에 복사해 적지 않습니다. 값이 없거나 읽을 수 없으면 필요한 값을 사용자에게 묻습니다.

공유 폴더에 들어간 파일은 publish 앱이 서빙합니다. 관리 화면은 박스 사실에 적힌 앱 주소의 `/publish/`입니다. 파일 링크 형식과 실제 호스트는 박스 사실의 규칙을 따릅니다.

내부 공유 링크를 여는 사람은 해당 박스의 접근 게이트를 통과할 수 있어야 합니다. 외부 공개 대상이 설정돼 있으면 관리 화면의 **Publish externally**에서 기간을 정해 공개하고, **My public links**에서 URL 복사·기간 변경·회수·만료 후 재게시를 할 수 있습니다. 지원하는 대상에서는 비밀번호 접근과 연결 문서 묶음도 제공합니다. 외부에 공개할 내용·기간·접근 방식은 사용자 요청을 따릅니다.

문서는 자동으로 외부에 공개되지 않습니다. 사용자가 공개를 요청하면 관리 화면에서 대상과 지원 기능을 확인합니다. 별도 대상이 없으면 Tailscale Funnel을 사용하며, 대상 설정은 [Publish 설정](../README.md)을 따릅니다. 내부 공유 URL과 외부 공개 URL을 구분해 전달하며 자격 증명은 문서·응답에 넣지 않습니다.

## 작성 원칙

- 첫 화면에 결론과 핵심 그림을 둡니다. 정확한 내용도 읽기 어렵다면 다시 씁니다.
- 독자가 배경을 모를 수 있다고 보고, 낯선 용어는 처음 나올 때 풉니다.
- 긴 설명은 `무슨 일 → 근거 → 이유 → 영향 → 다음 행동` 순서로 정리합니다.
- 수치에는 단위와 비교 기준을 붙입니다. 추정과 확인된 사실을 구분하고 빠진 범위도 적습니다.
- 표는 항목을 비교하거나 구조를 보일 때 씁니다. 핵심 메시지를 표 안에 숨기지 않습니다.
- 코드와 로그는 설명을 대신하지 않게 하고, 필요한 줄과 주변 맥락만 보여 줍니다.
- 출처가 있는 내용은 링크와 문서 이름을 함께 씁니다. 작성자나 날짜가 중요한 자료는 빠뜨리지 않습니다.
- 실측값, 추론, 미확정 내용을 구분합니다. 측정 범위와 조건을 생략하지 않습니다.
- 답을 받아야 하는 문서에는 응답 방법을 둡니다. 선택형 응답은 `templates/snippets/decision.html`을 사용합니다.
- 퀴즈가 필요하면 `templates/snippets/quiz.html`의 마크업을 사용합니다.
- 클래스명과 `data-*` 속성은 [`references/components.md`](references/components.md)의 계약대로 둡니다. 문서 고유 스타일에는 접두사를 붙입니다.
- 민감한 정보나 자격 증명은 공유 문서에 넣지 않습니다.

## HTML 골격

`<html lang="ko">`, 문자 인코딩, 모바일 viewport, 제목, 설명 메타데이터를 포함합니다. 본문은 `<main class="doc">` 안에 두고, 제목은 문서마다 하나의 `<h1>`로 시작합니다. 첫 요약은 `<p class="lead">`를 사용합니다.

공용 `doc.js`가 목차, 테마, 메모지, 결정 폼, 퀴즈를 처리합니다. 비슷한 기능을 페이지마다 새 스크립트로 다시 만들지 않습니다. 페이지별 JavaScript가 정말 필요하면 목적과 키보드 조작을 함께 확인합니다.

문서는 정적 링크로 열리므로 링크와 폼을 브라우저에서 직접 확인합니다. 키보드만으로 주요 동작을 쓸 수 있고, 이미지에는 대체 텍스트가 있는지 살핍니다.

제목 단계는 건너뛰지 않고, 링크에는 목적을 알 수 있는 문구를 씁니다. 색만으로 상태를 구분하지 말고 표에는 열 제목을 둡니다. 긴 문서는 목차나 짧은 진입점을 추가합니다.

## 템플릿과 공용 자산

새 문서는 [`templates/base.html`](templates/base.html)에서 시작합니다. 유형별 예전 템플릿은 기존 문서와의 참고용입니다. 작성 규칙은 [`references/authoring.md`](references/authoring.md), 클래스와 속성 계약은 [`references/components.md`](references/components.md)를 봅니다.

공용 자산은 문서에서 절대 경로로 불러옵니다. 이 주소는 publish 앱이 앱 폴더의 자산으로 연결합니다.

```html
<link rel="stylesheet" href="/_assets/doc.css">
<script type="module" src="/_assets/doc.js"></script>
```

두 줄은 각각 한 번씩 둡니다. 인쇄 스타일은 필요할 때만 `/_assets/doc-print.css`를 추가합니다. 템플릿의 제목, 요약, 본문을 채우고 쓰지 않는 예시를 지웁니다.

## 문서와 이미지

가능하면 단일 HTML로 유지합니다. 작은 아이콘이나 단순 도식은 인라인 SVG를 쓸 수 있습니다. 큰 스크린샷·도면은 문서와 함께 공유 폴더에 두고 상대 경로로 연결합니다. 본문 이미지는 읽기 좋은 크기로 표시하고, 원본을 클릭해 열 수 있게 합니다.

외부 폰트, CDN 스크립트, 원격 이미지는 기본값으로 쓰지 않습니다. 네트워크를 끊어도 문서의 본문과 주요 기능이 읽히도록 만듭니다. Mermaid는 인터넷에서 라이브러리를 가져오므로 꼭 필요한 경우에만 쓰고, 정적 공유 환경에서 실제로 그려지는지 확인합니다.

```html
<figure class="fig">
  <a href="img/result.png">
    <img src="img/result.png" alt="오류가 표시된 화면">
  </a>
  <figcaption>어느 부분을 봐야 하는지 짧게 설명합니다.</figcaption>
</figure>
```

이미지에는 내용을 설명하는 `alt`와 관찰할 점을 적은 설명을 둡니다. 표나 좌표처럼 구조가 중요한 정보는 이미지 대신 HTML 표로 재구성합니다.

큰 문서는 내용별로 `<section>`을 나누고 설명형 제목을 붙입니다. 반복되는 비교는 표로 모으되 한 셀 안에 긴 문단을 몰아넣지 않습니다. 가로 스크롤이 필요한 표는 모바일에서 핵심 값이 먼저 보이는지 확인합니다.

## 작성과 공유 순서

1. 박스 사실을 읽고 공유 폴더 규칙과 주소를 확인합니다.
2. 문서 이름은 짧은 영문·숫자·하이픈으로 정하고 HTML을 작성합니다. 자산과 템플릿을 사용하고 플레이스홀더를 모두 채우거나 지웁니다.
3. HTML의 제목, 요약, 링크, 이미지 경로, 민감한 정보 노출을 확인합니다. 로컬 미리보기는 공용 자산 경로가 제공될 때만 시각 검토에 씁니다.
4. 사용자가 공유를 요청했으면 publish 관리 화면에서 문서를 공유 폴더에 연결합니다. 원본 이동이 필요하면 복사와 심링크 중 어떤 방식을 쓸지 사용자 의도를 따릅니다. 직접 삭제하거나 공유 폴더의 파일을 일괄 정리하지 않습니다.
5. 실제 파일 URL을 브라우저에서 열어 스타일, 이미지, 폼을 확인합니다. 박스 사실의 URL 규칙에 맞는 주소로 요청해 응답을 확인한 뒤 전달합니다. 실측하지 않은 상태 코드를 성공으로 쓰지 않습니다.

공유 폴더에 이미 존재하는 파일은 `/_assets/`의 공용 스타일과 스크립트를 사용할 수 있습니다. 큰 이미지가 문서 옆에 있다면 이미지도 같은 상대 경로로 공유 폴더에 연결되어야 합니다.

문서에 쓰지 않은 자료를 무단으로 복사하거나 다른 공유 항목을 변경하지 않습니다. 외부 사이트에 의존하는 링크는 무엇을 여는지 설명하고 꼭 필요한 링크만 둡니다.

기존에 전달한 주소를 유지해야 하면 파일 이름을 바꾸지 말고 같은 경로에 내용을 갱신합니다.

## 공유 해제

사용자가 공유 해제를 요청하면 publish 관리 화면에서 해당 항목을 unpublish합니다. unpublish는 공유 등록을 해제하는 작업이며 원본 데이터 삭제를 뜻하지 않습니다. 결과를 확인하고 파일 URL이 더는 열리지 않는지 실측한 경우에만 그렇게 보고합니다.

## 결과 전달

공유를 마치면 문서 이름, 확인한 링크, 링크 응답 결과를 간단히 전달합니다. 문서가 아직 공유되지 않았다면 작업 위치를 알려주고 공유 등록이 남았다고 말합니다.
