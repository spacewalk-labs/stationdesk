# Connect your own domain to Publish

This guide is for a coding agent. The owner asked: "connect docs.example.com to my publish
app". Follow it step by step, stop where it says **Human**, and report what you changed.
Use the owner's real hostname wherever `docs.example.com` appears.

Publish serves external pages through Tailscale Funnel by default. Funnel only serves names in
the tailnet's own domain (`*.ts.net`) and only on ports 443, 8443 and 10000, so it cannot serve
`docs.example.com` ([Tailscale Funnel](https://tailscale.com/kb/1223/funnel)). To use your own
domain, put something else in front of the box. Two routes:

| | Route 1: Cloudflare Tunnel (recommended) | Route 2: Cloudflare Pages |
|---|---|---|
| Where pages are served | This box stays the origin | Cloudflare's network |
| Expiry and revoke | Keep working | Do not (see Route 2) |
| Password-gated `/g/` pages | Work | Do not work |
| Box off | Pages are unreachable | Pages stay up |
| Extra account | Cloudflare (free plan is enough) | Cloudflare |

Do Route 1 unless the owner has read the Route 2 tradeoffs and still wants it.

Placeholders: `$STATE` is the StationDesk state directory (`/opt/stationdesk/state` unless the
Publish Settings view shows another path for `publish.env`). Nothing below changes StationDesk's
code; it only edits `$STATE/publish.env` and adds two small services next to it.

## Route 1: Cloudflare Tunnel

`cloudflared` makes an outbound connection from the box to Cloudflare, and Cloudflare answers
`https://docs.example.com/...` through it. The origin is a small loopback nginx that serves only
the dedicated snapshot directories under `$STATE/publish/`, never the private share directory.
That is the same content Funnel serves, so existing snapshots keep working.

### Human does

1. Owns the domain (buy it at any registrar).
2. Has a Cloudflare account and the domain added to it with the registrar's nameservers changed
   to Cloudflare's. A locally-managed tunnel needs this
   ([prerequisites](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/create-local-tunnel/)).
3. Opens the login URL that `cloudflared tunnel login` prints, signs in, and picks the domain.
   You cannot do this for them. Print the URL, then wait.

### Agent does

**1. Install cloudflared.** On Debian/Ubuntu use Cloudflare's apt repository
(`https://pkg.cloudflare.com/cloudflared`); other systems: the
[downloads page](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/).
Check `cloudflared --version`.

**2. Create the tunnel** (documented CLI, see the
[tunnel guide](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/create-local-tunnel/)):

```sh
cloudflared tunnel login                      # Human opens the printed URL
cloudflared tunnel create stationdesk-publish # prints the tunnel UUID and credentials file
cloudflared tunnel route dns stationdesk-publish docs.example.com
```

The last command creates a `CNAME` to `<UUID>.cfargotunnel.com` in the owner's Cloudflare DNS.
That is the one DNS record, and the agent creates it; the human only needs the domain on
Cloudflare. It fails if `docs.example.com` already has a DNS record: stop and ask, do not
overwrite someone's record.

**3. Write the loopback origin.** Create `$STATE/publish-origin/nginx.conf`. StationDesk's
own nginx is not reused: its servers are generated by `stationdesk` and are retired when you
configure your own target.

```nginx
pid /opt/stationdesk/state/publish-origin/nginx.pid;
error_log /opt/stationdesk/state/publish-origin/error.log;
events {}
http {
    include /etc/nginx/mime.types;
    access_log /opt/stationdesk/state/publish-origin/access.log;
    client_body_temp_path /opt/stationdesk/state/publish-origin/tmp-body;
    proxy_temp_path /opt/stationdesk/state/publish-origin/tmp-proxy;
    fastcgi_temp_path /opt/stationdesk/state/publish-origin/tmp-fcgi;
    uwsgi_temp_path /opt/stationdesk/state/publish-origin/tmp-uwsgi;
    scgi_temp_path /opt/stationdesk/state/publish-origin/tmp-scgi;
    server {
        listen 127.0.0.1:19928;
        absolute_redirect off;
        add_header X-Robots-Tag "noindex, nofollow" always;
        location @none { return 404; }
        location = /robots.txt {
            default_type text/plain;
            return 200 "User-agent: *\nDisallow: /\n";
        }
        location ~ /\. { return 404; }
        rewrite "^/([a-z0-9][a-z0-9-]{2,63})$" /$1/ permanent;
        location / {
            root /opt/stationdesk/state/publish/public;
            try_files $uri $uri/index.html =404;
            add_header Cache-Control "no-store" always;
            add_header X-Robots-Tag "noindex, nofollow" always;
        }
        location ~ "^/g/(?<gslug>[a-z0-9][a-z0-9-]{2,63})(?<gpath>/.*)?$" {
            if (!-d /opt/stationdesk/state/publish/gated/$gslug) { return 404; }
            auth_basic "Restricted document";
            auth_basic_user_file /opt/stationdesk/state/publish/htpasswd/$gslug.htpasswd;
            alias /opt/stationdesk/state/publish/gated/$gslug$gpath;
            index index.html;
            error_page 403 =404 @none;
            add_header Cache-Control "no-store" always;
            add_header X-Robots-Tag "noindex, nofollow" always;
        }
    }
}
```

Replace `/opt/stationdesk/state` if `$STATE` differs, create the `tmp-*` parents with
`mkdir -p`, and check with `nginx -t -c <that file>`. Pick another loopback port if 19928 is in
use, and use the same port in step 4. Run it as a user service
(`~/.config/systemd/user/stationdesk-publish-origin.service`, `ExecStart=/usr/sbin/nginx -c
/opt/stationdesk/state/publish-origin/nginx.conf -g 'daemon off;'`, `Restart=always`), then
`systemctl --user daemon-reload && systemctl --user enable --now stationdesk-publish-origin`.
The nginx config is derived from [`funnel.conf`](../funnel.conf), with search engines always
told no: with your own domain the per-page search-engine switch is disabled.

**4. Write the cloudflared config**, `~/.cloudflared/config.yml` (fields as in the
[configuration file reference](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/configuration-file/);
the final catch-all rule is required):

```yaml
tunnel: <UUID from step 2>
credentials-file: /home/<user>/.cloudflared/<UUID>.json
ingress:
  - hostname: docs.example.com
    service: http://127.0.0.1:19928
  - service: http_status:404
```

Run it as a service, with the config path explicit because `sudo` changes `$HOME`
([Linux service](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/as-a-service/linux/)):

```sh
sudo cloudflared --config /home/<user>/.cloudflared/config.yml service install
sudo systemctl start cloudflared
```

If sudo is not available, run `cloudflared tunnel --config ~/.cloudflared/config.yml run` as a
user service instead. The box needs outbound access to Cloudflare on port 7844.

**5. Point Publish at the new origin.** Edit `$STATE/publish.env` (keep mode 0600; create it
if missing and keep every line already there, such as the site name). Add exactly these:

```sh
STATIONDESK_PUBLISH_PUBLIC_MODE=local
STATIONDESK_PUBLISH_BASE_URL=https://docs.example.com
STATIONDESK_PUBLISH_PUBLIC_DIR=/opt/stationdesk/state/publish/public
STATIONDESK_PUBLISH_GATED_DIR=/opt/stationdesk/state/publish/gated
STATIONDESK_PUBLISH_HTPASSWD_DIR=/opt/stationdesk/state/publish/htpasswd
STATIONDESK_PUBLISH_FUNNEL_PORT=
```

`publish.env` is read after `state/publish/funnel.env`, so these override the Funnel values. The
empty `FUNNEL_PORT` makes the Publish page stop describing the box as a Funnel target. Any of
`PUBLIC_MODE`, `INGEST_URL` or `BASE_URL` in this file also means "own target": a later
`stationdesk add publish` will not reopen Funnel and will retire the old one, so do not run it to
"fix" things; the variables are described in the app [README](../README.md) and
[examples/publish.env](../examples/publish.env). Until then the Funnel URL keeps answering;
old links keep working only while it does.

**6. Restart:** `systemctl --user restart stationdesk-publish`. Then confirm the tunnel is up
with `cloudflared tunnel list` (the tunnel shows active connections) and `systemctl status cloudflared`.

### Verify

Publish one test page from the manager (open, then one with a password), then:

```sh
curl -sI https://docs.example.com/<slug>/ | grep -i -e '^HTTP' -e x-robots-tag   # 200 + noindex, nofollow
curl -s  https://docs.example.com/robots.txt                                      # Disallow: /
curl -sI https://docs.example.com/g/<gated-slug>/ | head -1                       # 401, no password given
curl -sI -u user:password https://docs.example.com/g/<gated-slug>/ | head -1      # 200
curl -sI https://docs.example.com/ | head -1                                      # 404, no listing
```

Also open the manager, Settings: "External links" shows `This box · https://docs.example.com`,
and the Share popover now produces `https://docs.example.com/<slug>/` links. Revoke the test
page and confirm its URL returns 404 within a minute. If DNS has not propagated, wait and retry
before changing anything. Report the result of each check.

### Roll back to Funnel

1. Delete the six lines added in step 5 from `$STATE/publish.env`.
2. `stationdesk add publish` (re-reads the config and opens Funnel again), then
   `systemctl --user restart stationdesk-publish`.
3. Stop the tunnel and origin: `sudo systemctl disable --now cloudflared`,
   `systemctl --user disable --now stationdesk-publish-origin`.
4. Optional cleanup: the human deletes the `docs.example.com` `CNAME` in the Cloudflare DNS
   page; then `cloudflared tunnel delete stationdesk-publish`.

Links already shared with the custom domain stop working once the tunnel is stopped.

## Route 2: Cloudflare Pages (static copy, only with the tradeoffs accepted)

Pages hosts a static folder at `docs.example.com` without the box being reachable
([custom domains](https://developers.cloudflare.com/pages/configuration/custom-domains/),
[direct upload](https://developers.cloudflare.com/pages/get-started/direct-upload/)).
Publish does not do this itself: it keeps writing snapshots to
`$STATE/publish/public/`, and you upload that folder. Before the owner agrees, tell them what breaks:

- **Expiry and revoke stop working for the public.** Publish deletes a snapshot from the box,
  but the uploaded copy stays on Pages until you deploy again without it.
- **Password-gated pages cannot be served.** `/g/` needs the box's nginx (`auth_basic`).
  Do not upload `$STATE/publish/gated/`; gated publishing stays unusable on this route.
- **Every change needs a redeploy**, and the manager does not know about it. Its links point at
  the base URL whether or not the deploy has happened.
- Search-engine indexing is whatever Pages serves. To keep the default, put a
  `_headers` file in the uploaded folder with the line `/*` followed by an indented
  `X-Robots-Tag: noindex, nofollow` ([headers](https://developers.cloudflare.com/pages/configuration/headers/)).

If they still want it:

**Human does:** have a Cloudflare account; for an apex domain, the domain on Cloudflare; for a
subdomain such as `docs.example.com`, either that or a `CNAME` at their DNS provider to
`<project>.pages.dev` (after the domain is added in the Pages dashboard, Custom domains >
Set up a domain; adding the CNAME first gives a 522 error); approve `wrangler login`.

**Agent does:**

```sh
npx wrangler login                                  # Human approves in the browser
npx wrangler pages project create stationdesk-publish
npx wrangler pages deploy /opt/stationdesk/state/publish/public --project-name stationdesk-publish
```

Set `STATIONDESK_PUBLISH_BASE_URL=https://docs.example.com` in `$STATE/publish.env` (the other
variables as in Route 1 step 5, `PUBLIC_DIR` included, so that snapshots are still written),
restart `stationdesk-publish`, and re-run the `pages deploy` command after each publish, update
or revoke. Verify with `curl -sI https://docs.example.com/<slug>/` (200, `x-robots-tag`) and
that a revoked slug still answers until you redeploy; report that to the owner. Roll back as in
Route 1 (delete the `publish.env` lines, `stationdesk add publish`, restart) and remove the Pages
project and DNS record.
